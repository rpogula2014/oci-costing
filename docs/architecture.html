OCI cost pipeline · Go · OKE · PostgreSQL

OCI spend in SQL you can join

oci-costing pulls FOCUS and OCI-proprietary cost report CSVs from the tenancy reporting bucket every hour, normalizes them, and loads them into a partitioned PostgreSQL warehouse. Two static Go binaries in a FROM scratch image, deployed as a Kubernetes CronJob on OKE.

01

What it is

4 cards

A two-binary system that turns OCI cost CSVs into queryable Postgres rows. One binary loads, one binary orchestrates; both ship together in a single scratch image.

Binary · loader

oci-costing

Subcommands focus and oci. Reads .csv.gz files (single or folder), streams via gzip, writes to Postgres in 10k-row COPY batches inside a per-file transaction.

Binary · orchestrator

oci-load

Container entrypoint. Calls internal/ocireports in-process to pull CSVs from OCI Object Storage, then execs oci-costing twice (focus + oci).

Report formats

FOCUS + proprietary

focus_data_table for the vendor-neutral FinOps Open Cost & Usage schema; oci_cost_report for OCI's richer proprietary export with full tags/* in JSONB.

Runtime

Scratch on OKE

Hourly CronJob on OCI Kubernetes Engine. Image is FROM scratch (~18 MB, two static binaries, no shell), runs as UID 1000 with read-only rootfs.

02

Why it exists

4 drivers

OCI's console exposes cost data as CSV exports in a tenancy bucket. The FinOps team needs that data in SQL, freshly, with allocation tags intact, and without manual download steps.

Driver

Chargeback in SQL

Dashboards and chargeback queries can't pivot off CSV files. Granular line-item rows have to land in a warehouse with stable schemas so allocation logic is reproducible.

Driver

Multi-cloud comparability

FOCUS is the cross-vendor standard; loading it side-by-side with the OCI proprietary schema lets finance compare OCI spend against AWS/Azure on identical columns.

Driver

Catches corrections fast

OCI rewrites cost rows intra-day (lineItem/isCorrection). Hourly cadence means corrected rows show up within an hour, not the next morning.

Driver

Safe to re-run

Files dedupe on source_filename; an already-loaded file is a no-op. Re-running the job after a partial failure is the safest path forward, not the riskiest.

04

How — step by step

9 tiers

What happens between a CronJob tick and rows hitting Postgres. Read top-to-bottom; the numbers map to logical stages, not necessarily file boundaries.

  1. Cron tick K8s fires the CronJob on schedule 0 * * * *. The controller spawns a Job; the Job starts a single Pod with concurrencyPolicy: Forbid so two ticks never overlap.
  2. Orchestrator start Pod entrypoint is /oci-load. With no arguments it computes yesterday and today in UTC; with one argument it accepts yyyy, yyyy-mm, or yyyy-mm-dd for backfill.
  3. List + filter For each (date × {focus, cost}) ocireports.Download calls ListObjects on bucket bling with prefix FOCUS Reports/ or reports/cost-csv/, then keeps only objects whose TimeCreated matches the requested interval.
  4. Stream download Each match becomes a GetObject stream written to /data/focus/ or /data/cost/ on the pod's emptyDir. Output paths are validated to stay inside the target dir — no ../ escapes from malicious object names.
  5. FOCUS load oci-load execs /oci-costing focus /data/focus. The loader reads tags.yaml as an allow-list, opens each gzipped CSV, merges allowed tags/* into the JSONB tags column, and COPYs into focus_data_table in 10k-row batches.
  6. OCI proprietary load oci-load execs /oci-costing oci /data/cost. Same loader pattern but with auto-detection — every tags/* column lands in the JSONB tags on oci_cost_report, no allow-list.
  7. Dedupe + idempotence Before loading, each file is checked with SELECT EXISTS(SELECT 1 FROM <table> WHERE source_filename = $1). Already-loaded files are skipped and archived — re-running the job is always safe.
  8. Safety nets Each file runs inside its own transaction (BEGIN…COMMIT) and its own 30-minute context. A bad file marks FAIL and the batch continues; the process exits 2 if any failed, so k8s reports the Job as failed without losing the partial work.
  9. Pod exit Successfully loaded files move to /data/<type>/archive/; on Pod exit the entire emptyDir is wiped. Only Postgres state survives — the next tick repeats with a clean slate.
05

Design decisions

7 choices

Each row is a decision that pushed back on a default. Tradeoffs are listed honestly; none of these is free.

DecisionChoiceWhyTradeoff
runtime image FROM scratch Smallest attack surface; no shell, no libc, ~18 MB total. No kubectl exec debugging in prod — must rely on logs.
orchestration Go binary Replaces daily_load.sh so scratch is viable (no bash/date/tee needed). Bash script kept for local dev — two paths to maintain.
reports download in-process Go pkg One binary fewer in the image; no environment-variable indirection on the exec path. Pulls in oci-go-sdk/v65 as a dep.
tag handling split FOCUS uses an allow-list (tags.yaml); OCI proprietary auto-detects every tags/*. FOCUS exports hundreds of free-form tags; OCI's set is curated. If OCI's tag set ever grows noisy, JSONB will bloat the GIN index.
txn scope per file All-or-nothing per CSV — recovery is "rerun the job", never "fix half-loaded rows". Long files hold locks longer than per-batch commits would.
schedule hourly Picks up intra-day cost-report corrections within ~60 min. Re-pulls the same-day CSV many times; loader dedupes but bandwidth is spent.
concurrency Forbid + 50 min deadline No overlapping runs; no zombie pods running past the next tick. A slow run silently skips the next hour — watch MissingJob events.
06

Recent hardening

6 changes

Issues surfaced from code review and dependency scanning. None were exploitable in production, but each tightens the system or removes a latent risk.

Security

Path-traversal guard

internal/ocireports now resolves both OutputDir and the target path to absolutes, then filepath.Rel-checks the result. Object names containing ../ are rejected before any file is created.

Dependency

pgx CVE bump

jackc/pgx/v5 bumped v5.9.1 → v5.9.2 for GHSA-j88v-2chj-qfwx (placeholder confusion in dollar-quoted SQL). Not currently exploitable — we use positional params and CopyFrom.

Toolchain

Go 1.26.3

go.mod and base image pinned to 1.26.3 for the stdlib TOCTOU + html/template CVEs. Patch is pinned, not floating, so rebuilds are reproducible.

Reliability

Fail-soft loader

One bad CSV no longer aborts the batch. Each file marks DONE, SKIP, or FAIL; the process exits 2 if any failed so k8s alerts but doesn't lose work.

Reliability

Per-file context

Replaces the shared 30-minute batch context. One slow file timing out no longer poisons every file that comes after it.

Correctness

FOCUS tag synthesis

When a FOCUS CSV omits the Tags column entirely, allow-listed tags/* extras used to be silently dropped. The loader now synthesizes the tags column on the fly.
